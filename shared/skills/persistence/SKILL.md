# Сохранение и восстановление

Когда применять: Сохранить, открыть, найти, переименовать, удалить, копировать.

Входные данные: Список собственных дашбордов и текущий снимок.

Последовательность: Найди id через search_dashboards или context.saved_dashboards. Сохраняй снимок исходных строк, расчёты, версии, графики, KPI-рецепты, фильтры, zoom и hidden, даты и исходный запрос. save_dashboard as_new=false обновляет текущий, true создаёт копию. open_dashboard восстанавливает снимок без БД; обновление данных требует явного запроса fetch_data. Сохранение/переименование/удаление — последняя операция плана.

Инструменты: save_dashboard, search_dashboards, open_dashboard, rename_dashboard, delete_dashboard.

Ожидаемый результат: Доступный только владельцу воспроизводимый снимок.

Ограничения: Не угадывай id; не удаляй без явного запроса. Запрос «мои дашборды» не создаёт графики.

Когда context.workspace задан, пользователь явно выбрал дашборд для продолжения работы. Следующие расчёты, фильтры и перестроения относятся к его восстановленной таблице и автоматически обновляют ту же сохранённую запись. Сохраняй исходный запрос и пользовательское имя; не создавай новый снимок при каждом ответе. Для эксперимента пользователь выбирает «Создать копию», для отдельной работы — «Новый анализ». Без выбранного workspace новый финальный ответ с графиками автоматически сохраняется отдельным снимком; вызывать save_dashboard ради обязательного автосохранения не нужно.

Изменения фильтров, режима, серий, масштаба, формул и обновление данных в интерфейсе автоматически обновляют текущий снимок без вызова модели и без дубликатов. В карточке «Автосохранено»; «Название и копия» нужно только для имени или отдельной копии. В шапке чата «Мои дашборды» открывает список с исходными запросами, обеими датами, поиском и сортировкой. Библиотека общая для всех чатов одного владельца, включая поиск, переименование, удаление, копии, историю и публикации. «Открыть в этом чате» восстанавливает последнюю сохранённую версию в текущем чате и выбирает её для ИИ и «Данных»; имя видно у поля ввода. Это продолжение той же записи, а «Создать копию» создаёт отдельную. Переписки, черновики и текущие рабочие карточки разных чатов остаются отдельными. Другие владельцы эту библиотеку не видят.

Пример: «Сохрани как Продажи Q3» → save_dashboard(title=Продажи Q3).

Критерии проверки: После перезапуска значения, формулы, фильтры, серии и масштаб совпадают.

Состояния карточек, сессий и библиотеки используют общие сжатые блоки исходных данных и вычисленного снимка. Прежний формат читается без обязательной миграции. Настройки/история сохраняются атомарно. Серверный кеш готовых вариантов переживает перезапуск, браузерный кеш восстанавливает последний вид до проверки API; кеш не является подтверждением сохранения. Изменения данных, формул, конфигурации или рендера меняют ключ, кеш одной карточки не применяется к другой или чужому владельцу.

В «Действия» каждой карточки доступны скачивание PNG и автономного HTML, таблица с вычислениями CSV/Excel, история версий и публикация. Excel содержит значения вычисляемых колонок и лист с их определениями. Автосохранение добавляет версии при содержательных изменениях. Восстановление возвращает данные, вычисления, фильтры и графики, создавая новую версию; последующая история остаётся доступна. Для старых снимков история начинается с имеющегося сохранённого состояния. Удаление дашборда удаляет его историю и отзывает публикацию.

Публикация — явно созданный пользователем доступный по ссылке снимок графиков/KPI, без доступа к чату, исходной таблице или редактированию. Последующие правки не меняют публикацию до нажатия «Обновить публикацию». Ссылку можно скопировать или отозвать. Черновик ввода хранится отдельно для общего диалога и выбранного дашборда, восстанавливается при перезагрузке; очередь неотправленных запросов доступна для повтора. «Шаблоны запросов» вставляет редактируемый текст, не отправляя его автоматически.

Автосохранение и «Название и копия» в старой карточке относятся к ней самой. Контексты сообщений заморожены отдельно и восстанавливаются после перезапуска; обычная правка фильтра другой карточки не переключает выбранный workspace. Только явное «Продолжить работу» выбирает карточку для дальнейшего диалога. Для ответа без сохранившихся исходных данных UI показывает причину, а не подставляет произвольную свежую выборку.
