# Ошибки и ограничения

Когда применять: Пустой результат, недоступный источник, неверная формула, таймаут.

Входные данные: Результаты валидаторов, код ошибки, последнее правильное состояние.

Последовательность: Для пустоты попроси изменить фильтры. Для недоступной БД сообщи тип отказа без DSN. Для невалидной формулы объясни разрешённый язык. При таймауте модели не переключай модель или synthetic режим. Существенную неоднозначность уточняй. Ограничение row_limit отклоняет выборку, не выдаёт неполный итог. Сохраняй последнее корректное состояние.

Инструменты: inspect_schema, profile_table, validate_result.

Ожидаемый результат: Понятный способ исправления и сохранённое состояние.

Ограничения: Не раскрывать секреты, stack trace или скрытые рассуждения. Не считать timeout успешной операцией.

Пример: План 0 → выполнение «нет данных», а не 0% или Infinity.

Критерии проверки: Нет потери состояния; demo явно маркирован; ошибка не скрыта под фиктивным успехом.
