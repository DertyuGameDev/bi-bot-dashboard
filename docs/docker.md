# BI-бот дашборд — Docker

## Первый запуск

Нужен Docker с Compose. Подходят Docker Desktop, OrbStack, Docker Engine на Linux или Colima на macOS. Команда из корня клонированного репозитория:

```sh
./scripts/docker_start.sh
```

Откройте http://127.0.0.1:8080. При первом запуске нужен интернет для образов, зависимостей, исходного архива и модели. По умолчанию используются настоящая модель и данные источника.

Скрипт создаёт `.env.docker` с уникальными паролями. При первой интерактивной установке появляется мастер выбора провайдера, модели, Base URL и ключа; при повторном запуске существующая конфигурация сохраняется. API-варианты не требуют входа в Codex. Перед запуском выполняется запрос проверки JSON-протокола выбранной модели. [Все подключения и примеры](model-connections.md).

Если выбран Codex и на машине уже есть локальный `auth.json`, скрипт копирует только этот файл в приватный том `codex-auth`. Пользовательские конфиги, история Codex и файлы проекта модели не передаются. При отсутствии входа запускается `codex login --device-auth`: откройте предложенную ссылку и подтвердите код. Это стандартная [авторизация Codex](https://learn.chatgpt.com/docs/auth).

Затем Compose ждёт готовности PostgreSQL и успешного завершения импорта перед запуском приложения. Сервис просмотра стартует после готовности приложения; порядок основан на [healthcheck и depends_on](https://docs.docker.com/compose/how-tos/startup-order/).

## Сервисы и данные

| Сервис | Назначение |
| --- | --- |
| `app` | Чат, таблицы, Plotly-графики, библиотека, версии, экспорт. По умолчанию 127.0.0.1:8080. |
| `postgres` | Источник Puzzle RPA; порт не публикуется на хосте. |
| `import-data` | Однократный импорт 8 CSV. Имеет отдельные административные права. |
| `viewer` | Просмотр явно опубликованных снимков, без чата и редактора. 127.0.0.1:8082. |

Приложение подключается к источнику только как `rpa_reader`: SELECT на таблицы и read-only по умолчанию. Административный пароль ему не передаётся. Импорт атомарен; повторный запуск сохраняет существующий источник. Уже заполненная неизвестная схема не перезаписывается.

По умолчанию импорт скачивает опубликованный архив кейса. Если адрес недоступен или нужен запуск без загрузки архива, поместите исходный ZIP с путями `data/regions.csv`, `data/sales.csv` и остальными таблицами в `data/puzzle-data.zip` перед стартом. Каталог `data/` не попадает в Git и образ. Для другого HTTPS-адреса архива задайте `BI_DATA_URL` в `.env.docker`.

| Том | Содержимое |
| --- | --- |
| `app-data` | SQLite: переписка, таблицы, дашборды, версии, черновики и публикации. |
| `postgres-data` | PostgreSQL с исходными данными. |
| `codex-auth` | Авторизация Codex, доступная только контейнеру приложения. |
| `fixture-cache` | Скачанный архив для повторного импорта. |

`docker compose down` сохраняет эти тома. Не добавляйте `--volumes`, если хотите сохранить работу. Этот запуск создаёт отдельное хранилище: локальная `.local/state.sqlite3` автоматически в контейнер не переносится.

## Настройки

Пример доступен в `.env.docker.example`. Рабочий `.env.docker` создаёт стартовый скрипт; он исключён из Git. Если порт занят, измените `BI_PORT` и при необходимости `BI_VIEW_PORT` перед запуском. Для изменения порта viewer обновите также `BI_PUBLIC_BASE_URL`.

Существующие установки сохраняют `codex`, модель `gpt-6.1-terra`, reasoning `medium`. Для смены сервиса выполните `./scripts/docker_start.sh --configure-model`. ID модели вводится явно: её доступность зависит от вашего аккаунта или локального сервера. Смена провайдера не меняет источник и сохранённые дашборды. Повторный вход для Codex:

```sh
docker compose --env-file .env.docker run --rm --no-deps app codex login --device-auth
```

Только для явной проверки без ИИ можно задать `BI_MODEL_ADAPTER=demo`. Источник остаётся PostgreSQL, ответы в этом режиме детерминированные; это не замена проверки настоящей модели.

Для размещения на сервере задайте `BI_BIND_ADDRESS`, публичный адрес viewer в `BI_PUBLIC_BASE_URL` и используйте HTTPS reverse proxy. При HTTPS включите `BI_SECURE_COOKIE=true`. Основной чат и отдельный viewer обслуживаются разными портами. Не открывайте административную БД или служебные файлы в интернет.

## Обновление и остановка

```sh
git pull
./scripts/docker_start.sh
docker compose --env-file .env.docker ps
docker compose --env-file .env.docker logs --tail 100 app
docker compose --env-file .env.docker down
```

Пароли и авторизация берутся из уже существующих настроек и томов; скрипт не генерирует их заново при каждом запуске. Локальные токены, `.env`, `.local`, базы, загруженные данные и браузерные артефакты не включаются в репозиторий или build context.

## Резервная копия дашбордов

Онлайн-копия SQLite через встроенный backup API, без экспорта авторизации:

```sh
docker compose --env-file .env.docker exec -T app python -c \
  'import sqlite3; a=sqlite3.connect("/data/state.sqlite3"); b=sqlite3.connect("/data/backup.sqlite3"); a.backup(b); b.close(); a.close()'
docker compose --env-file .env.docker cp app:/data/backup.sqlite3 ./backup.sqlite3
```

Храните копию приватно. Для переноса исходной БД используйте отдельный `pg_dump`; для авторизации Codex на новой машине выполните вход заново. Экспорты HTML/CSV/Excel доступны также из интерфейса.
