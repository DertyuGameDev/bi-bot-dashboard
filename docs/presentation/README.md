# История Свята: демонстрация BI-бота

[Открыть презентацию](BI-бот%20дашборд%20—%20история%20Свята.pptx) · [Главный README](../../README.md)

**29 слайдов, один герой, 11 шагов обязательного сценария.** Небесно-голубая и белая палитра, редактируемые заголовки и подписи, реальные экраны MY. Портреты Свята взяты из предоставленной презентации ТФлоу; остальные персонажи в новую историю не перенесены.

## Как рассказывать

| Слайды | Действие в истории | Что объяснить |
| --- | --- | --- |
| 1–3 | Свят хочет понять, как идут продажи | Начинает с вопроса; ассистент уточняет период и продолжает тот же диалог |
| 4–7 | Проверяет таблицу и получает общую картину | Одна таблица питает графики и KPI; видны план, факт и выполнение |
| 8–12 | Находит нужный участок бизнеса | Поиск, каскад и множественный выбор; зум, подсказки, серии и переключатели |
| 13–17 | Проверяет гипотезу | Добавляет процент выполнения, меняет формулу, перестраивает рейтинг и читает итог |
| 18–21 | Сохраняет «Продажи Q3» и возвращается | Сначала выбирает июль — сентябрь; после перезапуска открывает тот же снимок |
| 22–26 | Продолжает и передаёт результат | Копия в другом чате, версии, экспорт, публикация и узкий экран |
| 27–29 | Понимает устройство и результат | Данные только для чтения, расчёты в приложении, Docker-запуск; решение остаётся за Святом |

Основной проход занимает примерно 8–12 минут при коротком объяснении каждого экрана. Подробные пояснения и ограничения включены в заметки докладчика.

Минимальный сквозной результат — вопрос → БД → единая таблица → интерактивный график → сохранение → восстановление — полностью включён. Целевые и дополнительные сценарии ТЗ показаны отдельно внутри истории: четыре графика, общие фильтры, вычисления, KPI, резюме, общая библиотека, версии, экспорт и публикация.

## На чём основаны экраны

- Сценарии взяты из приложенного бизнес-ТЗ Puzzle RPA и второго файла с требованиями к реализации, особенно раздела «Обязательный демонстрационный сценарий».
- Структура взята из «ТФлоу — третья версия. История хакатона»: герой → последовательность действий → результат → техническое объяснение. Исходная презентация сохранена отдельно и не изменялась.
- Скриншоты сняты **13 ноября 2026** в отдельном MY на PostgreSQL с настоящей `gpt-6.1-terra / medium`. Использован тестовый архив кейса Puzzle RPA. Это не данные действующей компании Свята.
- Конфигурация стандартного дашборда уточнена в диалоге; для демонстрации использованы настоящие фильтры, расчёты и настройки карточек. Содержимое переписки и цифры на скриншотах не дорисовывались. Технические кадры обрезаны до значимой области для читаемости.
- Реально проверены физический перезапуск QA, возврат к Q3 с формулой и четырьмя графиками, копия в другом чате, восстановление версии, загрузка HTML и его открытие без сервера. Публикация проверена через отдельный локальный viewer, после съёмки отозвана. Внешний туннель при этом прогоне не проверялся.
- Текущая демонстрация показывает самостоятельный MY и Plotly в соответствии с последующими решениями по проекту. Исторические требования к Telegram и старому SVG-интерактиву не представлены как текущие функции.

## Ограничения, которые нужно озвучить

HTML и ссылка содержат **снимок**. Изменение фильтров в редакторе не обновляет уже выгруженный файл и не меняет публикацию до её явного обновления. В HTML остаётся локальный интерактив, а обновление данных требует приложения. Временная внешняя ссылка с Mac зависит от запущенного туннеля.

Расчёт долей означает долю от общего объёма текущей выборки. Итоговое выполнение — отношение сумм. Для нулевого плана или отсутствующей базы предыдущего периода показывается отсутствие корректного показателя. Ограничение ТОП-N видно пользователю.

## Повторная сборка

Исходники оформления — `storyboard.json`, `build_deck.py` и `base/`; изображения — в `../images/`. Для сборки достаточно зависимостей проекта:

```sh
uv run python docs/presentation/build_deck.py
```

Команда пишет **черновик** в `.local/presentation-build/candidate.pptx`, не заменяя опубликованный файл. Финальный PPTX следует обновлять после проверки текста, структуры пакета и просмотра слайдов в PowerPoint. Заголовки, подписи, формы и заметки — нативные элементы PowerPoint; скриншоты и исходные портреты — изображения.
