# Техническое описание BI-бота

Пользователь задаёт вопрос и получает ответ модели и **единый интерактивный дашборд до четырёх графиков**. На компьютере рабочее окно разделено: слева узкая переписка, справа выбранный дашборд со всеми настройками. Интерактивные графики строит Plotly, палитры и общий стиль — Seaborn; доступны точные подсказки, серии, нативный зум и общие фильтры. Matplotlib/Seaborn используются для статических SVG/PNG. По ширине панели — сетка 2×2 или одна колонка. Белый интерфейс без декоративных блоков.

Telegram-версия удалена. Приложение работает целиком в MY: http://127.0.0.1:8080.

## Запуск в Docker

Нужен Docker с Compose. Установки Python, PostgreSQL и Node.js на хосте не требуется:

```sh
./scripts/docker_start.sh
```

Скрипт создаёт приватный `.env.docker` со случайными паролями, собирает приложение, настраивает Codex, импортирует источник и запускает сервисы. Откройте **http://127.0.0.1:8080**. Уже существующая авторизация Codex из локального `auth.json` копируется в отдельный Docker-том; при её отсутствии предлагается вход по коду устройства. Авторизация и пароли не входят в образ или Git.

Compose включает приложение, PostgreSQL 16, однократный импорт восьми таблиц и отдельный сервис просмотра опубликованных дашбордов на 8082. Сохранённые дашборды, источник и авторизация переживают пересоздание контейнеров. Если 8080 уже занят локальным MY, задайте `BI_PORT=18080` в `.env.docker`. Подробности, ручные команды, перенос и резервные копии — [docker.md](docker.md).

```sh
docker compose --env-file .env.docker ps
docker compose --env-file .env.docker logs -f app
docker compose --env-file .env.docker down
```

## Запуск без Docker

```sh
./scripts/start_local.sh
```

Нужны Python 3.11+, uv, PostgreSQL 16 и авторизованный Codex CLI. На новой машине с Homebrew:

```sh
brew install postgresql@16
./scripts/bootstrap_local.sh
./scripts/start_local.sh
```

Bootstrap скачивает [архив кейса Puzzle RPA](https://nc.puzzle-rpa.ru/s/gZaaDqjx2rcyfP4), создаёт отдельный кластер 127.0.0.1:55439 и SELECT-only роль. Для другой установки PostgreSQL задайте RPA_PG_BIN. Готовая БД: `uv sync --locked`, скопировать `.env.example` в `.env`, указать read-only DSN. Секреты только в `.env`, права 0600.

Явный режим проверки без БД и модели:

```sh
RPA_SOURCE=demo RPA_MODEL_ADAPTER=demo RPA_PORT=8083 uv run python -m MY
```

Демо использует синтетические данные и детерминированные сценарии, без ИИ; режим подписан во вкладке «Данные».

## Работа

- Настройки, фильтры, серии и масштаб сохраняются отдельно для каждого дашборда. Во время нового анализа можно открыть старый дашборд и менять его фильтры или графики: ответ ИИ не отменяет эти правки и не переключает выбранную вручную панель. При параллельной доработке одного исходного дашборда новый результат сохраняется отдельно, защищая предыдущий вариант.
- Уже открытые варианты выбора показываются из кеша браузера сразу, с последующим подтверждением автосохранения. Сервер также хранит готовые варианты и использует их после перезапуска. Кеш учитывает исходные данные, формулы, параметры графиков, фильтры и размер панели; обновление данных или вычислений не использует старые значения. Новое сочетание параметров сначала рассчитывается и затем попадает в кеш. Смена фильтра обновляет только выбранную карточку, не всю переписку. При запуске последний сохранённый вид появляется до завершения проверки API.

- В заголовке узкой переписки нажмите название чата — откроется список с поиском и переименованием. «＋» создаёт отдельный чат. Прежняя переписка находится в «Основном чате». Сообщения, текущие рабочие таблицы/карточки, черновики и очередь изолированы по чатам. Библиотека сохранённых дашбордов и собственные шаблоны общие для владельца: любой дашборд можно открыть в любом своём чате. Первый запрос предлагает имя нового чата, ручное имя сохраняется.
- Сообщение с графиками содержит компактную кнопку дашборда. Нажатие открывает его справа и выбирает для дальнейших вопросов; между дашбордами чата можно переключаться также списком над правой панелью. Следующий запрос продолжает выбранный анализ. «Новый анализ» справа очищает текущую рабочую область, сохраняя переписку и предыдущие дашборды. Справа доступны фильтры, серии/зум, вычисления, таблица, название/копия, экспорт, версии и публикация. Панели прокручиваются независимо.
- На окне уже 1100 px — вкладки «Переписка» и «Дашборд», обе области сохраняют контекст. На телефоне фильтры раскрываются в самой панели кнопкой «Фильтры и настройки», текущие регион/период видны в свёрнутом виде. Сначала видны KPI и график. Переход между чатами не отменяет серверный анализ: его ответ остаётся в исходной переписке и восстанавливается при возврате. Перезагрузка сохраняет выбранный чат, дашборд и позиции прокрутки.

- «Выдай выручку точек за 2026», «Продажи по регионам», рейтинги и динамика — по умолчанию интерактивный график. «За всё время» выбирает полную доступную историю; таблица показывается по явной просьбе.
- «Собери дашборд продаж за 2025 год» — ответ в переписке и выбранная справа карточка с максимум четырьмя SVG-графиками.
- Над общими фильтрами — восемь KPI-карточек: общий план, общий факт, выполнение плана, отклонение (абсолютное и в %), активные клиенты, точки, продукты и динамика к предыдущему периоду. Ниже открыты регион, точки, даты, разрез и метрика; группировка, вид и TOP-N доступны в раскрывающейся строке «Настройки графиков» с видимыми текущими значениями, затем графики. Доступны tooltip, серии, выделение масштаба и все точные значения. Фильтры меняют ту же карточку без модели.
- У всех графиков общие шрифты и палитра; стандартные оси, легенды, вычисляемые показатели и кварталы подписаны по-русски. Колесо мыши и трекпад нативно приближают область в Plotly. Данные, оси и подписи пересчитываются сразу в браузере; сервер асинхронно сохраняет масштаб, объединяя частые жесты. Зум, выделение области и «Перемещение» работают на столбцах, линиях, горизонтальных рейтингах, scatter, histogram и heatmap. В кольцевой диаграмме — выделение сектора кликом или через список, точная сумма и доля. Старый SVG-preview больше не участвует в интерактивности. Вне области графика работает обычная прокрутка. Также доступны выделение мышью, кнопки «+ / −», «Перемещение», двойной щелчок для сброса и клавиши `+`, `−`, `0` (сброс), когда график в фокусе. По умолчанию зум независим. «Связать масштаб по времени» связывает горизонтальную область временных графиков, сохраняя отдельные вертикальные оси; категориальные и круговые диаграммы не меняются. Зум, связь и скрытые серии сохраняются вместе с дашбордом. KPI от зума не меняются. Общий фильтр пересчитывает весь дашборд и сбрасывает прежние области масштаба. Точные значения доступны с клавиатуры в раскрываемой таблице под каждым графиком.
- Сразу под графиками — «Краткий итог»: факт и план за выбранный период, выполнение/отклонение, динамика и активные объекты. Он использует KPI своей карточки, обновляется вместе с её фильтрами и восстанавливается со снимком. Для метрик без плана, пустого выбора или отсутствующей базы сравнения показано соответствующее пояснение. Полный ответ ИИ остаётся слева в переписке.
- В списках фильтров есть «Найти значение…»: регион, точки, разрез, шаг времени и TOP-N в чате; регионы, точки, продукты и клиенты во вкладке «Данные». Поиск не учитывает регистр и различие ё/е, находит несколько слов в любом порядке. Он не сбрасывает выбор; после пересчёта остаются строка поиска, открытый список, фокус и его прокрутка. Escape закрывает список, стрелки/Space/Enter позволяют выбрать с клавиатуры.
- Фильтры каскадные: выбор региона сужает список торговых точек; несколько регионов дают объединение их точек, сброс возвращает весь список. Прежний выбор точек сбрасывается при смене региона. Пока список обновляется, устаревшие варианты недоступны для выбора. Все фильтры применяются ко всем графикам текущего дашборда и его KPI одним обновлением; исторические сообщения и сохранённые снимки остаются самостоятельными.
- В карточке доступны «Разрез», «Метрика», «По времени», «Вид». Разрез меняет сравнение плана/факта и строки тепловой карты; временные графики сохраняют ось времени. Метрики: объём продаж, сумма скидок, количество сделок, выполнение плана. Периоды: месяц, квартал, год. Виды: абсолютные значения, доли, динамика.
- Доли считаются от всего выбранного объёма до ограничения TOP-N. Выполнение плана — отношение сумм, а не среднее процентов. Динамика использует предыдущий календарный период из загруженных данных; для выполнения это изменение в п.п., для остальных метрик — в %. Без базы или при нулевом знаменателе значение не определено. KPI показывают итоги выбранного диапазона; у сделок и скидок план отсутствует. Для метрики выполнения верхние план/факт и отклонение остаются денежными, выполнение — в %, его динамика — в п.п. Переключатели сохраняются в снимках и работают без вызова модели.
- Активность — уникальные клиенты, точки и продукты с фактическими продажами; плановые строки не увеличивают счётчики. Динамика KPI сравнивает весь выбранный диапазон с предыдущим равным диапазоном: год с годом, квартал с кварталом, месяц с месяцем. Неполный год сравнивается с той же наблюдаемой частью предыдущего. Если в снимке нет базы, показано «Нет базы сравнения». Точные суммы доступны при наведении и с клавиатуры. Основные четыре показателя выделены крупнее; активность и динамика собраны в компактную строку. На узком экране показатели перестраиваются в две колонки.
- Каждый дашборд доступен из своего сообщения, включая предыдущие ответы. Фильтры, каскадные списки, серии, масштаб и автосохранение относятся к выбранной справа карточке. Выбор карточки явно переключает рабочую таблицу «Данные»; правки не меняют другие дашборды.
- «Мои дашборды» показывает одну общую библиотеку во всех ваших чатах. «Открыть в этом чате» восстанавливает последнюю сохранённую таблицу, формулы, настройки, графики и KPI в текущем чате и выбирает этот дашборд для дальнейших запросов ИИ. Открытие сохраняет ту же запись библиотеки; отдельная запись появляется только через «Создать копию» или новый анализ. Переписка из исходного чата не переносится. «Продолжить работу» в старой карточке выбирает её без дополнительного сообщения. Имя выбранного дашборда постоянно видно над вводом; «Таблица и расчёты» открывает его единую таблицу. Новые расчёты и перестроения автоматически обновляют эту же запись, сохраняя имя и исходный запрос. Обычная правка фильтра другой карточки не переключает выбранный контекст.
- В списке видны название, исходный запрос, дата/время создания и изменения, отметка «Сейчас в работе». Есть поиск по названию и запросу, сортировка по имени/созданию/изменению, переименование, удаление и создание копии. «Создать копию» выбирает отдельный снимок для эксперимента; «Новый анализ» снимает выбор и начинает отдельную работу, сохраняя историю и библиотеку. Без выбранного дашборда каждый новый визуальный ответ сохраняется отдельной записью.
- В снимке хранятся исходные данные, формулы, фильтры, серии и масштаб. Любые изменения фильтров, режима, серии, масштаба и формул, а также обновление данных автоматически сохраняют текущий дашборд. Во время фильтра — «Сохраняю…», после успешной записи — «Автосохранено». Кнопка «Название и копия» меняет название или создаёт отдельную копию; ручное сохранение не требуется. Дашборды доступны после перезапуска в том же браузере; список изолирован cookie владельца.
- Если выбран единственный месяц или объект, показывается настоящий столбик с подписью и точным значением. Линия или тепловая карта с единственным значением превращаются в столбик. Пустые данные явно обозначаются; период не расширяется автоматически.
- Во время обработки видны этап, число выполненных шагов и полученных строк. Сборка графиков показывает N из M. Анализ ReAct имеет неизвестное число шагов — полоса неопределённая, процент не выдумывается.
- Ввод доступен во время обработки, сообщения выполняются по очереди. После обновления страницы активная задача и её прогресс восстанавливаются. При перезапуске сервера прерванная задача получает явную ошибку и может быть отправлена повторно.
- «Покажи таблицу» — кнопка в ответе открывает «Таблица и расчёты» справа от переписки: заголовки, строки, страницы по 25/50/100 строк и формулы. Запрос таблицы и изменение вычислений открывают её автоматически. Она использует данные, фильтры и вычисления выбранного дашборда; графики доступны соседней вкладкой. CSV остаётся вложением, исходный табличный ответ сохраняется отдельным снимком.
- Вкладка «Данные»: подробная таблица с пагинацией, вычисляемые колонки, общие фильтры, сохранённые снимки и наблюдаемые шаги агента.
- «Добавь колонку выполнения плана», «Сохрани отчёт», CSV/Excel/PNG/HTML/SVG — расчёты и файлы из того же состояния.

## Файлы, черновики и версии

Над графиками выбранного дашборда есть кнопка «Скачать HTML». Она сохраняет один автономный файл с графиками, KPI и кратким итогом: его можно открыть в браузере без сервера и интернета, работают тултипы, серии и локальный масштаб. Фильтры в файле зафиксированы. Перед экспортом приложение дожидается сохранения текущих фильтров и масштаба. Кнопка относится именно к выбранной карточке, включая старые ответы и дашборды, открытые в другом чате. В «Действия» также доступны HTML, PNG, CSV и Excel с вычисляемыми колонками, история версий и публикация. Excel содержит три листа: данные с результатами вычислений, определения вычислений и параметры выбора.

Каждое содержательное автосохранение добавляет версию с датой и описанием изменений. «История версий» → «Восстановить» возвращает исходные строки, формулы, фильтры, графики и KPI без обращения к источнику. Восстановление создаёт новую версию и сохраняет последующие. У прежних дашбордов история начинается с их текущего сохранённого состояния. Исходные наборы переиспользуются между версиями, а не дублируются при каждом зуме.

Черновик сообщения автоматически записывается в браузер и SQLite. Для общего диалога и каждого выбранного дашборда он отдельный; после перезагрузки восстанавливается текст. Локальная копия работает без сети и синхронизируется при возвращении подключения. Неотправленная очередь также сохраняется и предлагает повторить запрос. Задержанная старая запись не затирает новый текст. «Шаблоны запросов» у ввода содержит три типовых запроса и позволяет добавлять, менять и удалять собственные; выбор вставляет текст для проверки перед отправкой.

## Поделиться ссылкой

Публикуется только явно выбранный снимок графиков и KPI, без редактора, чата или исходной таблицы. «Действия» → «Создать ссылку»; затем доступны копирование, «Обновить публикацию» и отзыв. Правки рабочего дашборда не меняют уже опубликованный снимок до обновления. Удаление дашборда отзывает его ссылку.

Для временной ссылки с этого Mac запустите отдельный сервис в другом терминале:

```sh
uv run python scripts/start_public.py
```

Он запускает `MY.public:app` на 127.0.0.1:8082 и открывает через SSH localhost.run только этот сервис просмотра. Основное приложение 8080 не публикуется. Временная ссылка работает, пока включён Mac и запущен сервис; её домен может измениться при переподключении. Текущий адрес берётся из `.local/public-address.json`. В интерфейсе это отмечено рядом со ссылкой. Для постоянного адреса разместите `MY.public:app` за HTTPS reverse proxy с доступом к той же SQLite и задайте `RPA_PUBLIC_BASE_URL=https://your-domain.example`. Учётные данные источника сервису просмотра не нужны.

## Модель и данные

Провайдер настраивается через [мастер подключения](model-connections.md): Codex, OpenAI API, Claude, Gemini, OpenRouter, DeepSeek, Ollama, LM Studio или произвольный совместимый сервис. Существующая конфигурация Codex gpt-6.1-terra / medium сохраняется до явной смены. Реальный ReAct: один выбранный инструмент → наблюдение/ошибка → новое решение до final. Скиллы выбираются через load_skill. Итоговый текст пишет модель; подставной KPI-сводки и хеширования контекста нет. Параметры RPA_AGENT_MAX_STEPS=24, RPA_AGENT_TIMEOUT=900, RPA_CHAT_HISTORY=100.

Preflight разбирает действия, конкретные графики, параметры и недостающие уточнения. `RPA_PREFLIGHT_MODE=agent` (по умолчанию) включает разбор в **первый шаг основной модели**, вместе с выбором инструмента, без отдельного модельного вызова. `local` — локальные правила с подсказкой основному агенту; `model` — отдельная модельная классификация; `off` — прежний ReAct без разбора. `decision` — настоящий локальный нейронный Kev-0.8B v1.0 (независимая Jev-style реализация), его вероятностная подсказка передаётся основному агенту. Для установки и запуска: `./scripts/setup_decision.sh`, затем `./scripts/start_decision.sh`; зависимости и веса отделены от приложения, сервер только на 127.0.0.1:8009. На проверенных русскоязычных запросах этот вариант хуже основной модели, поэтому по умолчанию сохранён `agent`. Классификация не исполняет правки; агент сверяет её с запросом и наблюдениями. Ошибка дополнительного классификатора не блокирует основной цикл. Разбор виден в «Как получен ответ», а в чате остаётся ответ модели. Для перестановки/удаления графиков и смены раскладки служит `update_dashboard`, сохраняющий id дашборда, фильтры, таблицу и формулы. [Сравнение вариантов и ограничения](preflight-comparison.md).

У каждого чата есть скрытая спецификация дашборда: цель, метрика, разрез, период, фильтры, группировка времени, вид значений, тип/раскладка графиков, top-N и фактические конфигурации/вычисления. Модель обновляет её через `brief_update` в обычном ReAct-шаге без отдельного модельного вызова. Обязательны цель, метрика и период; при неясном сравнении — ещё разрез. Если сведений не хватает, она задаёт короткий вопрос и сохраняет заполненное; загрузка данных/построение до уточнения блокируются. Ответ «за 2025 год» дополняет прежнюю цель. «За всё время» поддерживается как явный выбор, стандартный период молча не подставляется.

Спецификация хранится в состоянии конкретного чата SQLite, переживает перезагрузку и не переносится в соседние чаты. Графики и кеш не пересобираются от одного уточнения. Выбор сохранённого дашборда принимает его известные параметры, «Новый анализ» очищает спецификацию; фильтры активной карточки синхронизируются с ней. На приветствие или объяснение ожидающий запрос сохраняется. Обычный интерфейс остаётся чатом; технический JSON доступен только в диагностике и не попадает в публикацию/HTML. Включено по умолчанию: `RPA_DASHBOARD_BRIEF_ENABLED=true`; явный детерминированный demo-сценарий работает без моделирования этой памяти.

Месячный план/факт: fetch_data → pandas, без аналитических вычислений в SQL. Новые клиенты, контракты и исходные продажи: fetch_records / analyze_records / join_records. Именованные наборы сохраняются между шагами. Произвольные SQL/код модели не исполняются.

Источник изучен и импортирован из 8 CSV. Нельзя соединять сырые продажи с месячным планом: сначала приведение к общему зерну в pandas, затем проверяемое соединение. Выполнение — отношение сумм. План не распределяется на дни и клиентов; количество разных физических единиц не смешивается. [Архитектура](architecture.md).

Параметры графиков, раскрытые значения, фокус и прокрутка сохраняются при смене фильтра. Смена региона очищает несовместимый прежний выбор точек. Тепловая карта — агрегированная матрица «точки × периоды» с контрастной шкалой и значениями; TOP-N ограничивает строки с явным пояснением, все данные остаются в таблице и общих показателях. Последнюю серию скрыть нельзя.

Правая панель учитывает свою ширину и высоту: до четырёх графиков в общей сетке, один график использует всю ширину. На телефоне сетка перестраивается в колонку. Конфликт сохранённых регионов и точек исправляется с видимым пояснением до обращения к модели; настоящие пустые выборки сохраняются. Текст ИИ остаётся в переписке и помечается при последующей смене фильтров.
