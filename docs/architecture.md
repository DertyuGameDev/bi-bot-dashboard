# Архитектура MY

MY — FastAPI, обычный JS/CSS и Python-аналитика. Общий сервис shared/chat.py возвращает собственный текст модели, документы и один типизированный dashboard с максимум четырьмя SVG-графиками. Сообщение содержит снимок спецификаций, фильтров и версии таблицы. Telegram удалён.

## Агент и прогресс

Codex gpt-6.1-terra / medium запускается изолированно: пустой временный cwd, read-only, без встроенного shell, web и multi-agent. Credentials и вся таблица в prompt не передаются. На каждом шаге модель выбирает инструмент или final. Результат/ошибка инструмента — наблюдение следующего шага; скиллы загружаются по выбору. Итоговый answer не подменяется приложением.

POST /api/chat/jobs сохраняет owner-scoped задачу и немедленно отдаёт id. ThreadPoolExecutor выполняет анализ под блокировкой владельца. GET /api/chat/jobs/{id} возвращает этап, число шагов/строк, N/M рендера и итог. Активная задача находится через /api/chat/jobs/active после обновления страницы. Запросы с тем же request_id не дублируют задачу. При перезапуске сервера незавершённые задачи становятся явными ошибками; очередь не выдаёт подставной успех.

Прогресс отражает реальные события. В ReAct общее число шагов заранее неизвестно: total=null, UI показывает неопределённую полосу и счётчик завершённых шагов. На рендере total равно числу выбранных графиков. Код не генерирует фиктивные проценты.

## Данные и расчёты

Архив Puzzle RPA: regions=8, outlets=300, products=42, clients=180, contracts=617, sales=178739, sales_plan=122109, discounts=29550. Продажи 2023-01-01—2026-09-30; план до 2026-12-01.

Продажа — sale_id; скидка — discount_id; план — месяц × точка × продукт. Скидки суммируются на sale_id, продажи сворачиваются до зерна плана в pandas, затем outer merge validate=one_to_one. Справочники присоединяются many_to_one. Прямой join сырых продаж с планом запрещён.

Порядок: SELECT исходных полей/дат → проверка ключей → общая детализация pandas → фильтры → вычисляемые колонки → агрегаты. SQL без аналитических вычислений. Формулы — ограниченный AST без eval/exec. Доли/динамика/проценты не суммируются как аддитивные показатели; выполнение = sum(fact)/sum(plan). TOP-N ограничивает только рейтинг. Отсутствующий план остаётся null. Разные единицы quantity не смешиваются.

Для общих вопросов доступны fetch_records/analyze_records/join_records по фактической схеме: параметризованные значения, безопасные идентификаторы, лимит строк и проверка кардинальности. Новая регистрация — clients.registered_date, новый контракт — contracts.start_date; первая покупка требует min(sale_date) по всей истории клиента. Нулевые календарные дни учитываются при средних.

## Графики и интерфейс

Интерактивный слой — Plotly.js 4.1.1 из установленного plotly.py 7.1.0; цвета и heatmap-палитры формирует Seaborn. Тот же агрегированный pandas-frame используется для Plotly figure и статических SVG/PNG Matplotlib/Seaborn. Одна точка отображается столбиком. Колесо, выделение, pan и подписи обрабатывает Plotly в браузере, без SVG-transform и без ожидания API. Стабильные Plotly DOM, uirevision и очередь последних настроек предотвращают откат при асинхронном сохранении. Для heatmap сохранена совместимость прежних координат (+0.5), связываются только временные оси. Histogram и горизонтальная числовая ось не участвуют в календарной связи.

MY/dashboard.js строит единую сетку. Контейнерный breakpoint выбирает 2 колонки или одну. На компьютере выбранный дашборд находится справа от узкого чата; на телефоне панели переключаются вкладками. Модальный режим и sticky-заголовок удалены; на телефоне остаётся читаемая вертикальная прокрутка. CSS имеет единую систему стилей без старых каскадных переопределений. Header/history/progress/composer закреплены в явных строках Grid, история и таблицы имеют собственный scroll.

SQLite WAL хранит сессии и снимки исходных/материализованных строк, формулы/версии, конфигурации и переписку. Копии изменяются атомарно при успешной обработке; revision защищает мутации. Media/files и jobs проверяют cookie владельца. Matplotlib защищён глобальной блокировкой. Один процесс uvicorn, без корпоративного SSO и совместного редактирования. Для постоянной эксплуатации нужен работающий хост.

Библиотека `dashboards`, её `dashboard_versions`, `publications` и блоки `dashboard_blobs` принадлежат аккаунту cookie. Сессии, рабочие карточки, черновики, media и jobs остаются в пространстве выбранного чата. `account_owner` определяет аккаунт по зарегистрированному scope чата, а API предварительно проверяет принадлежность чата cookie. Открытие общей записи переносит её последнюю сохранённую таблицу и настройки в текущую рабочую область, добавляет карточку в текущую переписку и сохраняет общий saved_id. История сообщений исходного чата не переносится. Явная копия получает новый id.

При запуске MY до приёма запросов `migrate_shared_library` одной транзакцией объединяет прежние пространства чатов. Id записей, запросы, даты, сжатые состояния, номера версий и токены публикаций сохраняются. Контентные блоки копируются с дедупликацией до удаления старого пространства; ссылки в сессиях/карточках не переписываются. Маркер делает перенос однократным; сбой откатывает его целиком. Сам импорт модуля приложения или создание Store не запускает перенос пользовательских записей.

Plotly и русская локаль обслуживаются с локального сервера, без CDN. HTML-экспорт включает Plotly, локаль и тот же chart-widget: file:// работает без сети, с нативным зумом и пересчётом подписей. В круговой диаграмме выбранное пользователем поведение — выделение сектора и точная доля. Полные длинные названия остаются в tooltip, для осей используются короткие labelalias.
