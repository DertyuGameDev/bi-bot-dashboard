# Скрытая спецификация дашборда

Спецификация — это небольшая структурированная память диалога, которая передаётся модели в `context.dashboard_brief`. Она хранится в SQLite внутри состояния чата; это обеспечивает возврат к параметрам между запросами и перезапусками. Для независимых модельных запросов контекст передаётся явно, как описано в [OpenAI Conversation state](https://developers.openai.com/api/docs/guides/conversation-state). Доступ к данным и инструменты по-прежнему выбирает основной ReAct-агент.

## Сценарий

1. Пользователь: «Покажи сравнение выручки по торговым точкам».
2. Модель сохраняет цель, метрику amount и разрез outlet; период остаётся неизвестным. Ответ: «За какой период сравнить выручку торговых точек?» Источник не загружается, дашборд не создаётся.
3. Пользователь: «За 2025 год».
4. Модель дополняет тот же запрос диапазоном 2025-01-01 — 2025-12-31 и выполняет первоначальное сравнение. В библиотеке сохраняется исходный запрос вместе с уточнениями.

Этот сценарий прошёл с настоящей gpt-6.1-terra / medium на синтетических данных и отдельно в браузере на PostgreSQL. Ещё один чат с запросом о скидках сохранил свой незаполненный период, пока в первом строился дашборд.

## Содержимое

Обязательны конкретная аналитическая цель, метрика и период. Для сравнения, в котором непонятны объекты, модель включает обязательный разрез. Период — диапазон дат или явно запрошенная вся история; незаполненные границы диапазона считаются отсутствием периода.

Дополнительно хранятся разрез, группы регионов/точек/продуктов/клиентов, временная группировка, абсолютные значения/доли/динамика, тип и раскладка графиков, top-N, итоговые конфигурации графиков и вычисления, исходный запрос, до восьми последних уточнений, ожидающий вопрос, ревизия и время обновления. Неизвестное значение отличается от пустого выбора всех объектов: null и [].

В первом обычном ответе модели `brief_update` дополняет известные поля; null сохраняет прежнее, `clear_fields` явно стирает поле, `reset` начинает новый запрос с нуля. Смена метрики или разреза сама по себе не требует повторного вопроса о согласованном периоде. В последующих ReAct-шагах обновление обычно null. Отдельного модельного вызова для этой памяти нет. На разговорный вопрос память сохраняется.

## Ограничения исполнения

До заполнения обязательных полей блокируются загрузка/анализ данных, вычисления, построение и правки графиков, сохранение и экспорт через агента. Попытка инструмента возвращается модели как наблюдаемая ошибка протокола: модель должна исправить спецификацию или задать собственный вопрос. Инспекция схемы, скиллы и поиск/открытие уже существующих отчётов доступны для получения контекста.

Приложение не дописывает шаблонный вопрос к ответу: его формулирует модель. Результат с графиками/таблицей при незаполненной спецификации отклоняется. Перед созданием графика диапазон спецификации проверяется против действующих фильтров. Некорректные даты и диапазоны не принимаются. Неоднозначное advisory-состояние preflight с одновременно resolved и missing нормализуется в needs_model, чтобы корректное уточнение не превращалось в ошибку ответа.

Значения из уже выбранного дашборда известны и могут использоваться при продолжении работы. При открытии другого сохранённого дашборда принимаются его фактические параметры. «Новый анализ» очищает память, старые карточки остаются. Переключение чатов не меняет их спецификации. Поздний ответ фонового задания не перезаписывает спецификацию, которую пользователь уже сбросил или сменил.

## Сохранение и интерфейс

Поле dashboard_brief сохраняется тем же атомарным commit сессии, что и диалог. Старые сессии без поля читаются; существующий выбранный дашборд становится источником первоначальных известных параметров при следующем обращении. Массового переписывания старых данных при запуске нет. При ошибке модели остаётся последнее успешно сохранённое состояние.

Таблица не показывается отдельным виджетом в переписке; пользователь видит только вопрос или результат. JSON доступен в «Как получен ответ» для проверки. Параметры не попадают в опубликованный снимок/HTML, история соседних чатов недоступна. Смена спецификации без изменения данных/графиков не инвалидирует кеш визуализаций.

Реализация: shared/dashboard_brief.py, AgentStep.brief_update, shared/agent.py, сохранение и переключение workspace в MY. Включение: RPA_DASHBOARD_BRIEF_ENABLED=true (по умолчанию). Явный детерминированный DemoAdapter не имитирует работу нейронной памяти.

Проверки: tests/test_dashboard_brief.py; реальные ответы `.local/verification/brief-smoke.json`; браузерные этапы `.local/verification/brief-browser-core-results.json` и `brief-browser-resume-results.json`. В первом браузерном этапе выявлена потеря блока диагностики при принятии workspace; она исправлена, оставшиеся проверки продолжены на той же QA-сессии без повторных модельных запросов. Основная пользовательская SQLite не используется для тестовых правок.
