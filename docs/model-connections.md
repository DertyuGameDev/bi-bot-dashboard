# Подключение ИИ

Подключение настраивает владелец установки. Его ключ и доступ используются сервером приложения для всех его пользователей. Код проекта и Docker-образ не содержат авторизацию автора. При передаче компании она подключает собственный аккаунт или API-ключ.

## Мастер настройки

Docker, при первой установке из терминала:

```sh
./scripts/docker_start.sh
```

Повторная настройка:

```sh
./scripts/docker_start.sh --configure-model
```

Нужен только Docker с Compose; мастер работает внутри контейнера и не требует Python на хосте. Он меняет только поля подключения модели в `.env.docker`, сохраняя пароли БД, порты и остальные параметры. Ключ вводится скрыто; файл записывается атомарно с правами 0600. При отмене прежняя конфигурация остаётся. Переход к другому сервису не переносит туда ключ предыдущего.

Без Docker:

```sh
.venv/bin/python scripts/configure_model.py
.venv/bin/python scripts/check_model.py
./scripts/start_local.sh
```

Или `./scripts/start_local.sh --configure-model`. В этом режиме используется `.env`. При смене подключения работающий процесс нужно перезапустить. Источник PostgreSQL и пользовательское хранилище мастер не изменяет.

## Поддерживаемые подключения

| Значение `MODEL_ADAPTER` | Подключение | Base URL по умолчанию | Формат по умолчанию |
| --- | --- | --- | --- |
| `codex` | Codex CLI с собственным входом | CLI | JSON Schema |
| `openai` | OpenAI Responses API | `https://api.openai.com/v1` | JSON Schema |
| `openai_compatible` | Произвольный Chat Completions API | Вводится владельцем | JSON |
| `anthropic` | Claude Messages API | `https://api.anthropic.com/v1` | Вызов инструмента со схемой |
| `gemini` | Gemini через совместимый API | `https://generativelanguage.googleapis.com/v1beta/openai` | JSON |
| `openrouter` | OpenRouter | `https://openrouter.ai/api/v1` | JSON |
| `deepseek` | DeepSeek | `https://api.deepseek.com` | JSON |
| `ollama` | Локальный Ollama | `http://127.0.0.1:11434/v1` | JSON Schema |
| `lmstudio` | Локальный LM Studio | `http://127.0.0.1:1234/v1` | JSON Schema |

У всех API-профилей Base URL можно заменить. Для Responses-совместимого прокси выбирайте `openai`, для Chat Completions — `openai_compatible`, для Messages — `anthropic`. Адрес указывается **до** `/responses`, `/chat/completions` или `/messages`; путь метода добавляется автоматически. Токены и параметры запроса в URL не допускаются: используйте поле ключа или дополнительные заголовки.

Укажите точный ID модели из своего сервиса. Список моделей, тариф, доступ и качество выполнения агентных действий зависят от провайдера. Мастер не подменяет модель и не предполагает, что модель из аккаунта автора доступна получателю.

## Ручная конфигурация

В `.env.docker` используются переменные `BI_*`; в `.env` — те же имена с префиксом `RPA_*`.

Пример для собственного совместимого сервиса:

```dotenv
BI_MODEL_ADAPTER=openai_compatible
BI_MODEL=YOUR_MODEL_ID
BI_MODEL_BASE_URL=https://your-service.example/v1
BI_MODEL_API_KEY=YOUR_PRIVATE_KEY
BI_MODEL_API_FORMAT=json_object
BI_MODEL_API_HEADERS={}
```

Запустите `./scripts/docker_start.sh`. Значения в примере — заполнители, их нужно заменить. Не коммитьте рабочий файл. Для полной ручной настройки без терминального мастера сначала скопируйте `.env.docker.example` в `.env.docker`, задайте уникальные пароли БД и выбранное подключение.

Дополнительные параметры:

| Переменная без префикса | Назначение |
| --- | --- |
| `MODEL_API_FORMAT` | `auto`, `json_schema`, `json_object` или `prompt` |
| `MODEL_API_HEADERS` | JSON-объект дополнительных заголовков; например `{"api-key":"YOUR_KEY"}` |
| `MODEL_API_REASONING` | Необязательный effort для Responses API; пустое значение не отправляет параметр |
| `MODEL_MAX_OUTPUT_TOKENS` | Лимит ответа для Responses и Claude, по умолчанию 8192; Chat Completions использует лимит сервиса |
| `MODEL_TIMEOUT` | Таймаут одного ответа, по умолчанию 120 с |
| `REASONING` | Effort Codex; не отправляется другим сервисам |

Для корпоративного API с `api-key` вместо Bearer задайте его в `MODEL_API_HEADERS`; при необходимости можно заменить `Authorization`. Claude использует Messages API версии `2026-10-21` с Bearer-ключом. Совместимый шлюз с другой версией/авторизацией можно настроить дополнительными заголовками, например `anthropic-version` и `x-api-key`.

`json_schema` даёт наиболее строгий ответ, если модель его поддерживает. Если сервис отвергает этот параметр, выберите `json_object`. Для модели без обоих API-режимов есть `prompt`: схема передаётся в инструкции. В любом режиме приложение проверяет результат той же Pydantic-схемой. Некорректный, обрезанный ответ или отказ не выполняются. Автоматической замены провайдера, модели или режима на демо нет.

## Локальная модель и Docker

Ollama или сервер LM Studio запускаются отдельно; нужную модель нужно загрузить туда заранее. При Docker-настройке мастер предлагает `host.docker.internal` вместо `127.0.0.1`, потому что внутри контейнера loopback указывает на сам контейнер. Compose добавляет соответствующий адрес хоста. На Linux сервер модели должен слушать интерфейс, доступный Docker; не открывайте его в интернет. Для сервиса на другой машине укажите её доступный адрес.

Локальные профили допускают пустой ключ. Если у сервера включена авторизация, укажите его токен. Проект не скачивает веса и не обещает, что небольшая локальная модель будет выполнять сложные запросы с тем же качеством, что облачная.

## Проверка и ошибки

Docker-запуск до поднятия приложения выполняет:

```sh
docker compose --env-file .env.docker run --rm --no-deps -T app python scripts/check_model.py
```

Это настоящий запрос к выбранной модели с проверкой завершённого шага агента, без загрузки БД и пользовательских сообщений. Он расходует небольшой объём запросов/токенов сервиса. Проверка доступности HTTP или списка моделей не заменяет её. Режим `demo` явно отмечается как проверка без ИИ.

401 означает проблему ключа, 403 — прав, 404 — адреса/ID модели, 429 — лимитов или баланса. При 400 проверьте поддерживаемый формат и параметры. Тело ошибки провайдера не выводится, потому что оно может содержать ключ или запрос. Redirect не выполняется, чтобы не отправить авторизацию на другой адрес.

В браузере видны название провайдера и модель, ключи и дополнительные заголовки туда не попадают. Серверные администраторы управляют секретами; для доступа обычных пользователей в интернет дополнительно настройте авторизацию самого приложения и HTTPS.
